# Decisions

- Added a dedicated top-level `codex_external_attachments` store keyed as `session_key -> base_session_id -> record` instead of changing the existing `session_mappings` leaf shape.
- Modeled Codex attachment persistence with a focused `CodexExternalAttachmentRecord` dataclass plus a non-persisted `CodexExternalAttachmentBinding` helper for reverse-lookup results.
- Put create/read/delete/reverse-lookup behavior behind `SessionsFacade` helpers so downstream duplicate-attach logic can use one Codex-specific API instead of ad-hoc scans.
- Added a dedicated `modules/agents/codex/attach_service.py` that wraps `thread/list`, `thread/read`, `thread/resume`, and `thread/fork` through the existing `CodexTransport` JSON-RPC interface and returns structured workspace validation plus attach metadata.
- Refactored Codex’s persisted resume path to call the attach service instead of re-implementing `thread/resume` response normalization inside `agent.py`, while keeping transport ownership in `_get_or_create_transport()`.
- Validation statuses intentionally distinguish `valid`, `unverifiable`, `realpath_mismatch`, `repo_root_mismatch`, `fingerprint_mismatch`, and `cwd_mismatch_same_repo` so later UI/binding tasks can decide between inspect-only, resume, or fork without changing transport semantics.
- Normalized command-layer Codex picker metadata under `NativeResumeSession.locator["codex_attach"]`, including `inspect_first`, `allowed_actions`, an `inspect_payload`, and explicit `submission_payloads` carrying `action_intent` values for later UI/session-binding tasks.
- Kept WeChat on a message-only fallback path by blocking attach-aware Codex numeric/latest resume shortcuts and sending an explanatory i18n message instead of inventing a separate `/attach` command or binding from the command layer.
- Made `modules/agents/native_sessions/codex.py` prefer `CodexAttachService.list_threads()` for discovery and treat SQLite only as a compatibility fallback when the app-server catalog cannot be reached.
- Encoded Task 3’s attach policy at the provider layer: only workspace-valid + materialized threads advertise `['resume', 'fork']`, while fallback, unmaterialized, and workspace-mismatched candidates are marked `['inspect_only']` so downstream UI work can fail closed without changing the shared native session service contract.
- Extended `CodexSessionManager` instead of adding a parallel runtime store: lineage (`binding_origin`, `attach_mode`, source thread), pending attach aliases, and in-flight approval state now live beside the existing thread/session/cwd ownership map.
- Chose a split duplicate-attach policy: live duplicate `resume` attachments fork automatically to avoid silent shared writers, while already-forked or otherwise ambiguous duplicate state is rejected fail-closed instead of guessing.
- Kept approval handoff scoped to `external_attached` Codex sessions so ordinary Vibe-created Codex threads preserve the existing `approvalPolicy="never"` behavior and only resumed external state gets interactive approval routing.
- Implemented Task 5 by extending `SessionHandler.handle_resume_session_submission()` with a Codex-only attach state machine that reuses the existing confirmation/follow-up path, swaps the bound session id to the attach result thread id, and appends explicit provenance text for resumed-vs-forked external threads.
- Kept ordinary session mapping persistence string-based (`base_session_id -> resolved thread id`) and stored Codex external provenance separately under `codex_external_attachments`, using the post-attach resolved thread id as the source of truth for successful binds.
- Task 7 uses a shared `ResumePickerEntry` / `CodexAttachPresentation` model under `modules/im/resume_picker.py`, so Slack, Discord, Telegram, and Feishu only render attach-aware UI from normalized command-layer payloads instead of duplicating backend rules.
- Slack keeps the existing modal entrypoint but upgrades it to a select-then-inspect flow: selecting a Codex entry renders preview + validation + an explicit action selector in the same modal, while preview-only candidates close with an explanatory message instead of silently attempting attach.
- Discord, Telegram, and Feishu keep their current picker/card entrypoints and transition into a lightweight inspect step for Codex entries; only that inspect step can submit `action_intent` + `codex_thread_id` back to `handle_resume_session_submission()`.
- Added a dedicated focused suite at `tests/test_codex_attach_ui.py` instead of expanding Slack/Telegram platform tests, because Task 8’s exact verification command expects an attach-UI suite and the shared picker-payload builder is the least fragile place to assert inspect-only vs Resume/Fork behavior.
- Filled Task 8 coverage gaps entirely with mocked transport/service responses and existing lightweight stubs rather than changing production code, since the uncovered paths were already implemented guardrails that just lacked direct executable tests.
- Implemented Task 9 as a dedicated `codex_attach` scenario capability under `tests/scenarios/` plus `tests/scenario_harness/codex_attach.py`, keeping production code untouched and validating continuity through the real session-handler attach path.
- Fixed the regression-image OpenCode failure by making `scripts/prepare_three_regression.py` stage a local host OpenCode binary into `_tmp/three-regression/shared-home/.opencode/bin/opencode`, re-including only that file in `.dockerignore`, and having the integration `Dockerfile` copy that staged binary instead of downloading OpenCode during image build.
- Fixed Review B at the command-layer async seam instead of changing the Codex native-session provider: interactive `/resume` and WeChat resume listing now await thread-offloaded helpers, preserving attach catalog enrichment and `locator["codex_attach"]` payload generation unchanged.
- 2026-04-20: Kept Fix C minimal by changing only the confirmation preview lookup in `handle_resume_session_submission()` and covering it with a focused fork regression in `tests/test_resume_session.py`.
- 2026-04-20: Fixed Review A in two minimal seams only: Slack now routes `static_select` `session_select` events into `_handle_resume_modal_session_select()`, and shared resume-picker attach reconstruction now normalizes flattened Codex locator metadata back into the same explicit inspect/resume/fork payload shape used by the initial picker list.
